# Яндекс.Директ — план продвижения «День»

Статус: план v1 (06.11.2026). Допущение: кампании уже идут и являются главным источником трафика. Правило: **не масштабировать до** (1) фикса атрибуции в 1.3.1, (2) обновления privacy/Data safety, (3) baseline-метрик. Реконструкция кампаний — сразу. После получения статистики кабинета — скорректировать ставки и бюджеты (план v2).

## Экономика (важно: монетизации пока нет)

Приложение без подписок и покупок → прямая окупаемости Директа невозможна. Директ = инвестиция в базу пользователей. Поэтому:
- Рабочая метрика — **цена активного пользователя**: cost per `fill_completed`, а не CPI. CPI смотрим как вспомогательный.
- Порог cost per fill_completed задаём после baseline (трек 1, неделя 1) — до этого масштаб не трогаем.
- Февральский вопрос владельцу: монетизация (premium-режимы, темы, расширенный экспорт) — без неё масштабирование Директа упирается в потолок.

## Структура кампаний

| Кампания | Тип | Задача | Автостратегия |
|---|---|---|---|
| К1. Поиск — горячий спрос | Поиск, только смартфоны Android | спрос «хочу дневник-приложение» | сначала «установки», после ~50 событий `fill_completed`/мес → оптимизация на событие |
| К2. Поиск — конкуренты | Поиск | перехват аудитории Daylio, Journey, Diarium (ставим на бренд-ключи, в текстах НЕ упоминаем чужие бренды) | установки |
| К3. РСЯ — интересы | РСЯ | охват: саморазвитие, психология, привычки, осознанность; lookalike установивших (AppMetrica) | установки |
| К4. Ретаргетинг | РСЯ | сегмент AppMetrica «установили, не дошли до `fill_completed` за 3 дня» → вернуть к первой записи | клики/конверсии |

Бюджет при реконструкции: К1 40% / К2 15% / К3 30% / К4 15%. Масштабирование: +20–30% бюджета раз в 3–4 дня, только если cost per fill_completed в пороге.

## Креативы

Концепции (по 2–3 варианта на РСЯ, для поиска — тексты объявлений):
1. **«30 секунд вечером»** — боли «дневники надоедают»: один вопрос, пара строк, готово.
2. **«Год в пикселях»** — вау-визуал: 365 квадратов, каждый = настроение дня. Лучший креатив под РСЯ.
3. **«Серия»** — streak-мотивация: «3 дня подряд. Потом 7. Потом год».
4. **(с 1.4.0) «Итоги недели»** — новая фича: «приложение само собирает светлые моменты недели».
5. **НГ-сезон (с 15 дек):** «Подведи итоги года» + «Письмо себе на год вперёд» — отдельная сезонная кампания К5.

Требования: визуал — новая айдентика (после 1.4.0) → **все креативы переснять на редизайне**; до 1.4.0 не заливать новые крео массово, только текстовые тесты. Тексты объявлений — без обещаний, которых нет (привычки, синхронизация, облако).

## Трекинг и измеримость (критично)

1. Кампании должны ходить через **трекерные ссылки AppMetrica** (post-click attribution через Google Play Install Referrer) — иначе установки атрибутируются лево. Проверить: в AppMetrica → Рекламные кампании видны установки по каждой.
2. Ссылки: по трекеру на кампанию (не на группу — достаточно гранулярности: К1…К5).
3. Параметры трекера должны долетать до Amplitude как `acq_*` → после 1.3.1 проверить на 3–5 реальных установках из Директа.
4. Недельный ритм отчёта: расход / установки / CPI / `fill_completed` из AppMetrica × когорта `acq_campaign` в Amplitude (D3/D7). Файл — `.agents/memory/den-analytics.md`.

## Риски
- **Privacy policy** (фикс в 1.3.1): текущий текст заявляет «никакой аналитики» при живом Директе+AppMetrica — жалоба конкурента или проверка Play может остановить весь трафик. Самый срочный пункт.
- **Без атрибуции масштабирование = лотерея** — порог «не растить бюджет до acq_* в Amplitude» держим жёстко.
- **РСЯ-качество:** дешёвые установки РСЯ часто дают низкий D3 — К3 режем по retention-когорте, не по CPI.
