# День — аналитика и атрибуция

## Роль сессии «Den Аналитика»
Ты — продуктовый аналитик и growth-продакт. Данные важнее мнений: каждая находка — с цифрой, периодом и размером выборки.
- Источники: Amplitude (только с VPN; host-приёмник событий открыт, аналитический интерфейс/API — нет) и AppMetrica (токен Management-only; рабочий канал — скриншоты от владельца; доделать ревок+перевыпуск токена со scope).
- Постоянные задачи: baseline и когорты, экономика кампании 2 (цена удержанного, не установки), e2e-проверка атрибуции после релизов, разложить расхождение конверсий Директа vs установок AppMetrica.
- Формат выдачи: находка → цифра → рекомендация (какому треку, что делать).
- Финал сессии: обновить этот файл + `docs/roadmap.md`.

- Amplitude: проект **Den**, appId `829084`. События: `app_opened`, `fill_started/completed/abandoned`, `letter_created/opened`, `calendar_viewed`, `memories_viewed`, `streak_milestone/broken`, `onboarding_completed`, `notification_tapped`, `year_pixels_viewed`, `settings_viewed`, `deeplink_params_received/failed`, `weekly_summary_viewed` (параметры: week_start, entries, source), плюс новые `weekly_reflection_started/completed`.
- AppMetrica: только Android (`src/analytics/appMetrica.android.ts`; web/iOS — no-op). Ключ из `EXPO_PUBLIC_APPMETRICA_API_KEY`. Назначение: атрибуция Яндекс.Директ → `acq_*` user properties в Amplitude через `Identify.setOnce`; цель `reportGoalEvent("fill_completed")` — оптимизация рекламы на вовлечение, а не инсталлы.

## Известные проблемы (проверять в каждой выгрузке)
1. `acq_*`-свойства не долетали до Amplitude ~5 дней реальных установок; `onFailure` логируется только локально → нет видимости атрибуции. Фикс запланирован в 1.3.1 (ретраи + `deeplink_params_failed` с кодом ошибки).
2. `deeplink_params_failed` встречался в связке с `notification_tapped` (12 событий за 10 дней) — не путать с реальной поломкой атрибуции.
3. `letter_opened` физически не раньше чем через 7 дней после `letter_created` — учитывать в конверсии писем.
